### 🚨 CRITICAL VULNERABILITIES (Fix Immediately)

#### **1. Hardcoded API Keys & Secrets in Environment Variables**
**Files:** `AuthContext.tsx`, `server/index.ts`

```tsx
// AuthContext.tsx - Lines 35-36

const GOOGLE_ANDROID_CLIENT_ID = process.env.EXPO_PUBLIC_ANDROID_CLIENT_ID ?? "";
```

**Risk:** `EXPO_PUBLIC_` prefix means these are **embedded in the client bundle** and visible to anyone who decompiles the APK. Google Client IDs can be extracted and abused.

**Exploit Scenario:**
- Attacker decompiles APK → extracts Google Client ID → creates fake app using your OAuth credentials → Google flags YOUR app for abuse → OAuth suspension

**Fix:**
```tsx
// Use expo-constants for server-side only secrets
// Or switch to Expo's built-in auth which handles this securely
// NEVER use EXPO_PUBLIC_ for sensitive credentials
```

#### **2. Server-Side Request Forgery (SSRF) via URL Parsing**
**File:** `app/qr-detail/[id].tsx` (Lines 340-345)

```tsx
function handleOpenDestination() {
  if (!guardLink?.currentDestination) return;
  const dest = guardLink.currentDestination;
  Linking.openURL(dest.startsWith("http") ? dest : `https://${dest}`);
}
```

**Risk:** No URL validation before `Linking.openURL()`. A malicious QR code with `javascript:` or `intent://` scheme could execute arbitrary code.

**Exploit Scenario:**
- Attacker creates QR with content: `javascript:alert(document.cookie)`
- User scans → "Open Destination" → JavaScript executes in browser context
- Or: `intent://settings/#Intent;action=android.settings.SETTINGS;end` → opens system settings

**Fix:**
```tsx
function handleOpenDestination() {
  if (!guardLink?.currentDestination) return;
  const dest = guardLink.currentDestination;
  
  // STRICT validation
  const allowedSchemes = ['https:', 'http:'];
  let url: URL;
  try {
    url = new URL(dest.startsWith("http") ? dest : `https://${dest}`);
  } catch {
    return;
  }
  
  if (!allowedSchemes.includes(url.protocol)) {
    console.warn('Blocked unsafe URL scheme:', url.protocol);
    return;
  }
  
  // Block private IPs
  const hostname = url.hostname;
  if (/^(192\.168\.|10\.|127\.|0\.0\.0\.0|localhost)/.test(hostname)) {
    return;
  }
  
  Linking.openURL(url.toString());
}
```

#### **4. Firestore Security Rules Bypass via Client-Side Logic**
**File:** `AuthContext.tsx` (Lines 120-140)

```tsx
// Client-side "hard gate" for unverified emails
if (!adapterUser.emailVerified) {
  setUser(null);
  setToken(null);
  setIsLoading(false);
  return;

```

**Risk:** This is **client-side only**. A malicious user can bypass this by directly calling Firestore APIs with a valid (but unverified) token.

**Impact:** Unverified users can read/write Firestore data despite the UI blocking them.

**Fix:** Enforce email verification in **Firestore Security Rules**, not just client code:
```javascript

  allow read, write: if request.auth != null 
    && request.auth.token.email_verified == true;
}
```

#### **5. Username Enumeration & Race Condition**
**File:** `AuthContext.tsx` (Lines 60-75)

```tsx
async function reserveUsername(uid: string, displayName: string): Promise<string> {
  for (let attempt = 0; attempt < 5; attempt++) {
    const candidate = await generateUniqueUsername(displayName);
    try {
      await db.set(["usernames", candidate], { userId: uid, reservedAt: db.timestamp() });
      return candidate;
    } catch {
      // Race condition: another user claimed this username
    }
  }
  // Fallback with UID suffix
  const fallback = "user" + uid.slice(-8).toLowerCase().replace(/[^a-z0-9]/g, "x");
  // ...
}
```

**Risk:**
1. **Username enumeration**: The loop reveals whether a username exists (via the catch block timing)
2. **Race condition**: Two users with same displayName can collide, wasting attempts
3. **Predictable fallback**: `user` + last 8 chars of UID is guessable

**Fix:** Use Firestore transactions for atomic username reservation:
```tsx
async function reserveUsername(uid: string, displayName: string) {
  return db.runTransaction(async (transaction) => {
    const candidate = await generateUniqueUsername(displayName);
    const ref = db.collection("usernames").doc(candidate);
    const doc = await transaction.get(ref);
    if (doc.exists) {
      throw new Error("Username taken");
    }
    transaction.set(ref, { userId: uid, reservedAt: firebase.firestore.FieldValue.serverTimestamp() });
    return candidate;
  });
}
```

#### **6. CORS Misconfiguration on Server**
**File:** `server/index.ts` (Lines 25-50)

```typescript
function setupCors(app: express.Application) {
  const origins = new Set();
  // Adds REPLIT_DEV_DOMAIN and REPLIT_DOMAINS
  // Allows ANY localhost origin
  const isLocalhost = origin?.startsWith("http://localhost:") || origin?.startsWith("http://127.0.0.1:");
  if (origin && (origins.has(origin) || isLocalhost)) {
    res.header("Access-Control-Allow-Origin", origin);
    res.header("Access-Control-Allow-Credentials", "true");
  }
}
```

**Risk:**
- `Access-Control-Allow-Credentials: true` + wildcard-like localhost allowance = **CSRF vulnerability**
- Any website running on `localhost` can make authenticated requests to your API
- In production, if `REPLIT_DOMAINS` is misconfigured, arbitrary origins may be allowed

**Fix:**
```typescript
const ALLOWED_ORIGINS = [
  'https://yourapp.com',
  'https://app.yourdomain.com',
  // Explicitly list production domains
];

function setupCors(app: express.Application) {
  app.use(cors({
    origin: (origin, callback) => {
      if (!origin || ALLOWED_ORIGINS.includes(origin)) {
        callback(null, true);
      } else {
        callback(new Error('Not allowed by CORS'));
      }
    },
    credentials: true,
    methods: ['GET', 'POST', 'PUT', 'DELETE'],
    allowedHeaders: ['Content-Type', 'Authorization']
  }));
}
```

#### **7. No Rate Limiting on API Endpoints**
**File:** `server/index.ts`

**Risk:** The server has no rate limiting middleware. Attackers can:

- Spam QR code generation
- DDoS the comment system
- Exhaust Firebase read quotas

**Fix:**
```typescript
import rateLimit from 'express-rate-limit';

const apiLimiter = rateLimit({
  windowMs: 15 * 60 * 1000, // 15 minutes
  max: 100, // limit each IP to 100 requests per windowMs
  message: { error: 'Too many requests, please try again later.' }
});

app.use('/api/', apiLimiter);
```

#### **11. Information Disclosure via Error Messages**
**File:** `server/index.ts` (Lines 200-210)

```typescript
app.use((err: unknown, _req: Request, res: Response, next: NextFunction) => {
  const error = err as { status?: number; statusCode?: number; message?: string };
  const status = error.status || error.statusCode || 500;
  const message = error.message || "Internal Server Error";
  console.error("Internal Server Error:", err);
  return res.status(status).json({ message });
});
```

**Risk:** Stack traces and internal error messages are leaked to the client.

**Fix:**
```typescript
app.use((err: unknown, _req: Request, res: Response, next: NextFunction) => {
  console.error("Internal Server Error:", err);
  const status = (err as any).status || (err as any).statusCode || 500;
  // Don't leak internal error details
  const message = status === 500 ? "Internal Server Error" : (err as any).message;
  return res.status(status).json({ message });
});
```
