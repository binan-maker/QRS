# 🔍 Profile Page: Complete Performance, Cost & Architecture Analysis

Based on your Expo Router + Firebase stack and the symptoms (slow mount, high Firestore reads, janky scroll, laggy buttons/texts), here's a **production-grade, multi-file breakdown** of why the Profile page is slow/expensive and exactly how to fix it.

---

## 📉 Root Cause Analysis: Why It's Slow & Expensive

| Symptom | Technical Root Cause | Impact |
|---------|----------------------|--------|
| **2-5s white screen** | Sequential `await` for user profile, stats, generated QRs, followers, settings | Blocks render until all resolve |
| **High Firestore cost** | `onSnapshot` on static-ish data + full document fetches + no pagination | ~50-200 reads/tab switch |
| **Scroll jank** | `FlatList` without virtualization, inline computations, un-memoized cards | Drops below 40 FPS on mid-tier devices |
| **Button lag/flickers** | Unstable refs (`() => fn`), direct async writes on tap, no `disabled` state | Main thread blocked, double-tap bugs |
| **Text/Image layout shift** | Dynamic height calculations, uncached avatars/QRs, synchronous date/number formatting | CLS > 0.15, perceived "heavy" UI |
| **Expensive re-fetches** | No `staleTime`, re-fetches on every tab navigation | Wastes bandwidth & Firestore quota |

**Current Pattern (Expensive):**

### 2️⃣ `features/profile/hooks/useProfile.ts` (Data Layer)
**Current Problem:** Sequential promises, no caching, re-fetches on mount, no field projection.

**✅ Fix: Parallel Fetch + React Query + Field Selection**
```typescript
import { useQuery } from '@tanstack/react-query';
import { doc, getDoc, collection, query, orderBy, limit, getDocs } from 'firebase/firestore';
import { db } from '@/lib/firebase';

async function fetchProfile(uid: string) {
  const [userSnap, statsSnap, qrsSnap] = await Promise.all([
    getDoc(doc(db, 'users', uid), { fields: ['displayName', 'avatarUrl', 'verified', 'plan'] }),
    getDoc(doc(db, 'users', uid, 'stats', 'aggregate')),
    getDocs(query(
      collection(db, 'users', uid, 'generatedQrs'),
      orderBy('createdAt', 'desc'),
      limit(10)
    ))
  ]);

  return {
    user: userSnap.data(),
    stats: statsSnap.data(),
    recentQrs: qrsSnap.docs.map(d => ({
      id: d.id,
      type: d.data().qrType,
      status: d.data().securityStatus || 'safe',
      createdAt: d.data().createdAt?.toDate?.() || new Date(),
      // ✅ Pre-truncate to avoid UI lag
      preview: d.data().content?.slice(0, 60)
    })),
    sections: [
      { id: 'header', type: 'header', data: userSnap.data() },
      { id: 'stats', type: 'stats', data: statsSnap.data() },
      { id: 'recent_qrs', type: 'list', data: qrsSnap.docs.map(d => ({ id: d.id, ...d.data() })) }
    ]
  };
}

export function useProfile(uid: string) {
  return useQuery({
    queryKey: ['profile', uid],
    queryFn: () => fetchProfile(uid),
    staleTime: 1000 * 60 * 5,     // Cache 5 mins
    gcTime: 1000 * 60 * 30,       // Keep 30 mins
    refetchOnWindowFocus: false,
    refetchOnMount: false,
  });
}
```

## 💾 Caching Strategy: What to Cache vs What Not To

| Data Type | Cache? | Tool | TTL | Why |
|-----------|--------|------|-----|-----|
| **User profile & plan** | ✅ Yes | React Query + MMKV | 5 min | Rarely changes, gates features |
| **Aggregate stats** | ✅ Yes | React Query | 3 min | Append-only, expensive to compute live |
| **Recent QRs/History** | ✅ Yes | React Query + FlashList | 2 min | Virtualized + paginated, safe to stale |
| **Settings/Preferences** | ✅ Yes | MMKV | Persistent | Sync once on app start |
| **Avatars/QR Thumbnails** | ✅ Yes | `expo-image` memory-disk | Indefinite | Heavy network cost, zero reload reason |
| **Real-time alerts** | ❌ No | `onSnapshot` | Real-time only | Low volume, time-sensitive |
| **Button states (loading/edit)** | ✅ Yes | Zustand/Context | Session | Prevents re-sync on tab switch |

**Firestore Cost Rule:** Profile pages are **read-heavy but update-rare**. `onSnapshot` charges 1 read/doc on attach + every change. Replace with `getDoc`/`getDocs` + `staleTime` + pull-to-refresh. Use `increment()`/`arrayUnion` for stats to avoid full doc reads.

## 🖼️ UI/UX & Button/Text Optimization Checklist

### 🔘 Buttons (Edit Profile, Share, Export, Delete, Settings, QR Actions)
| Anti-Pattern | ✅ Fix |
|--------------|--------|
| `onPress={() => handleAction(id)}` | `useCallback` + stable reference |
| No `disabled` during async | `disabled={isPending}`, show spinner, `hitSlop={8}` |
| Dynamic inline styles | Extract to `StyleSheet.create()` outside component |
| Unstable event refs | Wrap in `useMemo` or declare outside render |

### 📝 Text Rendering (Dates, Stats, Status, URLs)
| Anti-Pattern | ✅ Fix |
|--------------|--------|
| `new Date().toLocaleString()` in render | `useMemo` + `date-fns`/`dayjs` |
| Long URLs without truncation | `numberOfLines={1}` + `ellipsizeMode="tail"` |
| Re-computing trust scores/formatting | Pre-compute at fetch time or `useMemo` |
| Dynamic height calculations | Fixed `minHeight` + `flex` layout |

### 📐 Layout & Scroll Performance
- Replace `<ScrollView>` with `<FlashList>` or `<FlatList>` + `removeClippedSubviews`
- Set `windowSize={4}` to limit off-screen renders
- Avoid `LayoutAnimation` on profile sections (causes jank on Android)
- Use `collapsable={false}` only when necessary (default `true` improves perf)
