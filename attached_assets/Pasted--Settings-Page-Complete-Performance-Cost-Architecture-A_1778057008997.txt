# 🔍 Settings Page: Complete Performance, Cost & Architecture Analysis

Based on your Expo Router + Firebase stack and the symptoms (slow mount, high Firestore reads, janky toggles, laggy text/buttons), here's a **production-grade, multi-file breakdown** of why the Settings page is slow/expensive and exactly how to fix it.

Unlike other pages, the Settings page is often **deceptively expensive** because it tries to sync *every* preference in real-time and fetches large configuration objects unnecessarily.

---

## 📉 Root Cause Analysis: Why It's Slow & Expensive

| Symptom | Technical Root Cause | Impact |
|---------|----------------------|--------|
| **1-3s white screen** | Sequential `await` for User Profile, App Config, Notification Tokens, Subscription Status, Privacy Policy version | Blocks render until all resolve |
| **High Firestore cost** | `onSnapshot` on static config docs + fetching full `users/{uid}` doc just for settings | ~20-50 reads/session (wasted) |
| **Toggle Lag/Jank** | Direct Firestore write on every toggle click without debouncing or local state buffering | UI freezes waiting for network; double-tap bugs |
| **Button flicker** | Unstable refs (`() => fn`), no `disabled` state during async updates | Visual stutter, accidental double-submissions |
| **Text/Layout Shift** | Dynamic loading of "Version", "Terms Date", "Plan Name" causes layout reflow | Perceived slowness, CLS > 0.1 |
| **Expensive Re-renders** | Entire settings list re-renders when one toggle changes (no memoization) | Battery drain, heat generation on device |

## 📂 Multi-File Breakdown & Fixes (Mapped to Your Repo)

### 1️⃣ `app/(tabs)/settings.tsx` (Main Screen)
**Current Pattern (Expensive):**
```tsx
// ❌ Monolithic, sequential fetches, no skeleton, direct writes
export default function Settings() {
  const [config, setConfig] = useState(null);
  const [prefs, setPrefs] = useState({});

  useEffect(() => {
    const load = async () => {
      const c = await getAppConfig(); // Static! No need to wait
      const p = await getUserPrefs(uid); 
      setConfig(c); setPrefs(p);
    };
    load();
  }, []);

  const handleToggle = async (key, value) => {
    await updateDoc(doc(db, 'users', uid), { [`prefs.${key}`]: value }); // Writes immediately
    setPrefs(prev => ({ ...prev, [key]: value }));
  };

  return (
    <ScrollView>
      {config && <Header title={config.appName} />}
      <ToggleRow label="Notifications" value={prefs.notifications} onChange={handleToggle} />
      <ToggleRow label="Dark Mode" value={prefs.darkMode} onChange={handleToggle} />
      {/* ... 20 more rows ... */}
    </ScrollView>
  );
}
```

**✅ Optimized Pattern:**
```tsx
export default function Settings() {
  const {  settings, isLoading } = useSettings(uid);
  const { mutate: updatePref } = useUpdatePreference();

  if (isLoading) return <SettingsSkeleton />;

  return (
    <FlashList // Even simple lists benefit from virtualization if long
      data={settings.sections}
      estimatedItemSize={60}
      renderItem={({ item }) => <SettingSection section={item} onUpdate={updatePref} />}
      removeClippedSubviews
      keyExtractor={(item) => item.id}
    />
  );
}
```

### 2️⃣ `features/settings/hooks/useSettings.ts` (Data Layer)
**Current Problem:** Fetching dynamic data that rarely changes. No caching strategy.

**✅ Fix: Local Storage First (MMKV) + React Query Fallback**
*Settings should be read from local storage (MMKV) instantly, then synced with server in background.*

```typescript
import { useQuery, useMutation } from '@tanstack/react-query';
import { mmkv } from '@/lib/storage/mmkv'; // Fast local storage
import { doc, getDoc, updateDoc } from 'firebase/firestore';
import { db } from '@/lib/firebase';

// 1. Instant Load from MMKV
const getCachedSettings = (uid: string) => {
  const raw = mmkv.getString(`settings_${uid}`);
  return raw ? JSON.parse(raw) : null;
};

export function useSettings(uid: string) {
  return useQuery({
    queryKey: ['settings', uid],
    queryFn: async () => {
      // Parallel fetch only what's needed
      const [userSnap, configSnap] = await Promise.all([
        getDoc(doc(db, 'users', uid), { fields: ['prefs', 'plan', 'email'] }),
        getDoc(doc(db, 'config', 'global')) // Static app config
      ]);

      const data = {
        prefs: userSnap.data()?.prefs || {},
        plan: userSnap.data()?.plan || 'free',
        appVersion: configSnap.data()?.version || '1.0.0'
      };

      // ✅ Save to MMKV for instant next load
      mmkv.set(`settings_${uid}`, JSON.stringify(data));
      return data;
    },
    staleTime: 1000 * 60 * 30, // Cache 30 mins (Settings change rarely)
    initialData: () => getCachedSettings(uid), // ⚡ INSTANT LOAD
  });
}

// 2. Optimistic Update Mutation
export function useUpdatePreference() {
  return useMutation({
    mutationFn: async ({ uid, key, value }: any) => {
      await updateDoc(doc(db, 'users', uid), { [`prefs.${key}`]: value });
    },
    onMutate: async ({ uid, key, value }) => {
      // Cancel outgoing refetches
      await queryClient.cancelQueries({ queryKey: ['settings', uid] });
      
      // Snapshot previous value
      const previous = queryClient.getQueryData(['settings', uid]);
      
      // Optimistically update local cache
      queryClient.setQueryData(['settings', uid], (old: any) => ({
        ...old,
        prefs: { ...old.prefs, [key]: value }
      }));
      
      // Update MMKV immediately
      const newData = { ...previous, prefs: { ...previous.prefs, [key]: value } };
      mmkv.set(`settings_${uid}`, JSON.stringify(newData));

      return { previous };
    },
    onError: (err, variables, context) => {
      // Rollback on failure
      queryClient.setQueryData(['settings', variables.uid], context.previous);
    },
    onSettled: () => {
      queryClient.invalidateQueries({ queryKey: ['settings'] });
    }
  });
}
```

### 3️⃣ `features/settings/components/SettingRow.tsx` (UI Item)
**Current Problem:** Inline handlers, un-memoized components, heavy re-renders.

**✅ Fix: `React.memo` + Stable Handlers**
```tsx
import { memo, useCallback } from 'react';
import { View, Text, Switch, StyleSheet } from 'react-native';

export const SettingRow = memo(({ label, value, onChange, description }: Props) => {
  // ✅ Stable handler reference
  const handleToggle = useCallback(() => {
    onChange(!value);
  }, [value, onChange]);

  return (
    <View style={styles.row}>
      <View style={styles.textContainer}>
        <Text style={styles.label}>{label}</Text>
        {description && <Text style={styles.desc}>{description}</Text>}
      </View>
      <Switch
        value={value}
        onValueChange={handleToggle}
        trackColor={{ false: '#cbd5e1', true: '#3b82f6' }}
        thumbColor="#fff"
      />
    </View>
  );
});

const styles = StyleSheet.create({
  row: { flexDirection: 'row', justifyContent: 'space-between', alignItems: 'center', paddingVertical: 14, paddingHorizontal: 16 },
  textContainer: { flex: 1, marginRight: 12 },
  label: { fontSize: 16, fontWeight: '500', color: '#1e293b' },
  desc: { fontSize: 13, color: '#64748b', marginTop: 2 }
});
```

### 4️⃣ `lib/services/config-service.ts` (Static Config)
**Current Problem:** Fetching global app config from Firestore on every mount.

**✅ Fix: Bundle Static Config or Use Remote Config**
*Don't use Firestore for static app config (version, terms URL, feature flags).*

```typescript
// Option A: Hardcode in app (Fastest, requires app update to change)
export const APP_CONFIG = {
  version: '1.2.0',
  termsUrl: 'https://qrguard.in/terms',
  supportEmail: 'support@qrguard.in'
};

// Option B: Firebase Remote Config (Best for dynamic flags without DB reads)
import remoteConfig from '@react-native-firebase/remote-config';

export async function getRemoteConfig() {
  await remoteConfig().fetchAndActivate();
  return {
    maintenanceMode: remoteConfig().getValue('maintenance_mode').asBoolean(),
    minAppVersion: remoteConfig().getValue('min_app_version').asString()
  };
}
```

## 💾 Caching Strategy: What to Cache vs What Not To

| Data Type | Cache? | Tool | TTL | Why |
|-----------|--------|------|-----|-----|
| **User Preferences** | ✅ **YES (Critical)** | MMKV + React Query | Persistent | Must load instantly; sync in background |
| **App Config (Version/Terms)** | ✅ Yes | Bundle / Remote Config | Indefinite | Static, no DB reads needed |
| **Subscription Status** | ️ Partial | React Query | 5 min | Check receipt validation occasionally |
| **Notification Tokens** | ❌ No | Sync on change only | 0 | Write-only mostly |
| **Logout/Clear Data Actions** | ❌ No | Immediate execution | 0 | Security critical |
| **UI State (Expanded Sections)** | ✅ Yes | MMKV / Zustand | Session | Preserve user scroll position |

**Firestore Cost Rule:** Settings are **write-heavy but read-rare**. Avoid `onSnapshot`. Use `getDoc` + `staleTime`. For toggles, use **Optimistic UI** so the user feels instant response, while the write happens in the background.

## 🖼️ UI/UX & Button/Text Optimization Checklist

### 🔘 Toggles & Buttons (Save, Logout, Delete Account)
| Anti-Pattern | ✅ Fix |
|--------------|--------|
| Direct `await updateDoc()` in `onChange` | Use `useMutation` + Optimistic Update |
| No feedback on slow network | Show temporary "Saving..." spinner or toast |
| `onPress={() => logout()}` | `useCallback` + `disabled={isPending}` |
| Missing confirmation dialogs | Add `Alert.alert` for destructive actions (Delete Account) |

### 📝 Text Rendering (Versions, Emails, URLs)
| Anti-Pattern | ✅ Fix |
|--------------|--------|
| Concatenating strings in render | Pre-compute constants outside component |
| Loading "Checking version..." text | Show cached version immediately, update if mismatch |
| Long email truncation | `numberOfLines={1}` + `ellipsizeMode="middle"` |

### 📐 Layout & Scroll Performance
- Use `FlashList` even for short lists if sections are complex.
- Group settings into sections (Account, Privacy, App) to reduce re-render scope.
- Avoid animating the entire list when a single toggle changes.
