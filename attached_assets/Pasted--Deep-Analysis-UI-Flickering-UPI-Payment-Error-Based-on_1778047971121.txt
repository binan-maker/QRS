## 🟨 Issue 1: Watch/Follow Button Flickering

### 🔎 Root Cause Analysis
The flickering pattern (`Watching 1 → Unwatched → Watching 1`) is a classic **state synchronization race condition** in React Native + Firebase. Here's what's happening in your codebase:

| Phase | What Happens | Why It Flickers |
|-------|--------------|-----------------|
| `onPress` | Local state updates immediately (`isWatching = true`) | UI shows "Watching 1" |
| Firestore Write | `docRef.update({ watchers: increment() })` executes async | Button remains active |
| `onSnapshot` Listener | Fires with server state *before* write completes | Overwrites local state → shows "Unwatched" |
| Write Completes | Server state updates → listener fires again | Re-renders → shows "Watching 1" |
| Dev Mode | `React.StrictMode` double-invokes handlers | Exacerbates flicker in development |

### 📍 Likely Code Location in Your Repo
```
app/qr-detail/[id].tsx
├── const [isWatching, setIsWatching] = useState(q.isWatching)
├── const handleToggleWatch = async () => {
│     setIsWatching(true) // ⚠️ Optimistic update
│     await firestore().collection('users').doc(uid).update(...)
│     // Missing: isLoading state, error rollback, listener debounce
│   }
└── useEffect(() => { subscribeToUserDoc(uid) }, [uid]) // ⚠️ Competes with local state
```

### ✅ Solution: Stable State Management Pattern

#### Step 1: Replace direct Firestore writes with React Query `useMutation`
```typescript
// hooks/useQrFollowWatch.ts
import { useMutation, useQueryClient } from '@tanstack/react-query';
import { doc, updateDoc, increment } from 'firebase/firestore';
import { db } from '@/lib/firebase';

export function useToggleFollow() {
  const queryClient = useQueryClient();

  return useMutation({
    mutationFn: async ({ userId, targetId, type }: { userId: string; targetId: string; type: 'follow' | 'watch' }) => {
      const userRef = doc(db, 'users', userId);
      const field = type === 'follow' ? 'followingCreators' : 'watchedQrs';
      
      // Use Firestore array operations for atomic updates
      await updateDoc(userRef, {
        [field]: arrayUnion(targetId)
      });
    },
    onMutate: async ({ userId, targetId, type }) => {
      // Cancel outgoing refetches so they don't overwrite optimistic state
      await queryClient.cancelQueries({ queryKey: ['user', userId] });
      
      // Snapshot previous value
      const previous = queryClient.getQueryData(['user', userId]);
      
      // Optimistically update cache
      queryClient.setQueryData(['user', userId], (old: any) => ({
        ...old,
        [type === 'follow' ? 'followingCreators' : 'watchedQrs']: 
          [...(old?.[type === 'follow' ? 'followingCreators' : 'watchedQrs'] || []), targetId]
      }));
      
      return { previous };
    },
    onError: (err, variables, context) => {
      // Rollback on failure
      queryClient.setQueryData(['user', variables.userId], context.previous);
    },
    onSettled: () => {
      // Refetch to ensure server consistency
      queryClient.invalidateQueries({ queryKey: ['user'] });
    }
  });
}
```

#### Step 2: Update Button Implementation (Prevents Double-Trigger)
```tsx
// app/qr-detail/[id].tsx

  {isFollowing ? 'Following' : 'Follow'}
</Button>
```

#### 🔧 Why This Fixes It:
- ✅ **Atomic updates**: `arrayUnion` prevents race conditions
- ✅ **Optimistic cache**: React Query handles UI updates without competing with `onSnapshot`
- ✅ **Disabled state**: Blocks rapid taps & `React.StrictMode` double-invocation
- ✅ **Rollback on error**: UI never gets stuck in inconsistent state

## 🟥 Issue 2: UPI "Could Not Load Banking Name" Error

### 🔎 Root Cause Analysis
This error occurs when the UPI app receives a malformed `upi://` deep link. UPI apps strictly validate parameters before resolving VPA names. Here's what breaks it:

| Problem | Impact on UPI App |
|---------|-------------------|
| Missing `&cu=INR` or `&mc=0000` | App skips name resolution → "Could not load banking name" |
| Unencoded `&pn=` or `&tn=` | Special characters break query parsing → VPA resolution fails |
| Invalid VPA format (`pa`) | Must be exactly `name@provider`. Spaces/caps break parsing |
| Using `Linking.openURL()` without `encodeURIComponent` | `&` in transaction note terminates URL early |
| Amount not formatted to 2 decimals | Some apps reject `am=100` instead of `am=100.00` |

### ✅ Solution: Standardized UPI Intent Builder

#### Step 1: Create a Robust UPI URI Generator
```typescript
// lib/upi-intent.ts
export function buildUpiIntent({
  vpa,
  payeeName,
  amount,
  transactionNote,
  merchantCode = '0000'
}: {
  vpa: string;
  payeeName: string;
  amount?: string;
  transactionNote?: string;
  merchantCode?: string;
}): string {
  // 1. Validate VPA format
  const vpaRegex = /^[a-zA-Z0-9._-]+@[a-zA-Z0-9]+$/;
  if (!vpaRegex.test(vpa)) throw new Error('Invalid VPA format');

  // 2. Sanitize & encode
  const encodedName = encodeURIComponent(payeeName.trim());
  const encodedNote = transactionNote ? encodeURIComponent(transactionNote.trim()) : '';
  
  // 3. Format amount (UPI requires 2 decimals if provided)
  const formattedAmount = amount ? parseFloat(amount).toFixed(2) : '';

  // 4. Build standard UPI URI
  const params = new URLSearchParams({
    pa: vpa,
    pn: encodedName,
    mc: merchantCode,
    ...(formattedAmount && { am: formattedAmount }),
    ...(encodedNote && { tn: encodedNote }),
    cu: 'INR',
    mode: '02' // Forces name resolution mode in most UPI apps
  });

  return `upi://pay?${params.toString()}`;
}
```

#### Step 2: Update Payment Button with Fallback & Validation
```tsx
// components/QrPaymentButton.tsx
import { Linking, Alert, Platform } from 'react-native';
import { buildUpiIntent } from '@/lib/upi-intent';

export function PayButton({ vpa, payeeName, amount, note }: Props) {
  const handlePay = async () => {
    try {
      const uri = buildUpiIntent({ vpa, payeeName, amount, transactionNote: note });
      
      // Check if any UPI app is installed
      const supported = await Linking.canOpenURL(uri);
      if (!supported) {
        Alert.alert('No UPI App', 'Please install GPay, PhonePe, or Paytm to continue.');
        return;
      }

      await Linking.openURL(uri);
    } catch (err) {
      console.error('UPI Intent failed:', err);
      Alert.alert('Payment Error', 'Could not initiate payment. Check VPA format and try again.');
    }
  };

  return <Button title="Pay via UPI" onPress={handlePay} />;
}
```

#### 🔧 Why This Fixes It:
- ✅ `mode=02` + `mc=0000` forces UPI apps to resolve payee name from NPCI database
- ✅ `encodeURIComponent` prevents `&` or spaces from breaking query parsing
- ✅ VPA regex validation blocks malformed addresses before redirect
- ✅ `Linking.canOpenURL()` prevents silent failures on devices without UPI apps
- ✅ Standardized `URLSearchParams` ensures parameter order compatibility across GPay/PhonePe/Paytm
