Ahmed, the delay you're seeing on tab clicks and the Firestore cost spike are directly related. 🔍 Part 1: Why Every Tab Click Is Delayed
The Core Problem: Route Mount Blocking
When you tap a tab icon, Expo Router unmounts the current screen and mounts the target screen. If the target screen does any of these on mount, it blocks the UI thread:

💰 Part 3: Reduce Firestore Costs (Keep 100% of Features)
Firestore bills per document read/write/delete. Your current pattern likely reads the same documents repeatedly on every tab switch. Here's how to cut costs by 60-80% without losing functionality:
🔹 1. Enable Offline Persistence (Instant 50% Reduction)
Firestore caches locally. Once enabled, repeated reads of the same data hit the cache, not the server.

Real-time listeners cost 1 read per document per update. If a collection has 1,000 docs, you're burning 1,000 reads instantly.
