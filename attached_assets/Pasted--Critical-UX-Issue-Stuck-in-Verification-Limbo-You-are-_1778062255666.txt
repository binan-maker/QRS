# 🚨 Critical UX Issue: "Stuck in Verification Limbo"

You are absolutely right. This is a **major user experience failure**:

```
❌ User Signs Up → Email not verified → Weeks pass → Email expires/deleted
❌ User tries to Login → "Please verify your email" 
❌ No "Resend Verification" button on Login screen
❌ User is STUCK: Can't login (unverified), Can't signup (email exists), Can't resend
```

This causes **support tickets, user churn, and lost trust**. Here's the complete fix.

---

## 🔍 The Root Problem

| Current Flow | Why It Fails |
|--------------|--------------|
| Login → `!emailVerified` → `signOut()` → Show error | User is logged out, has no way to trigger a new verification email |
| Verify screen has "Resend" but user never reaches it from Login | Login screen doesn't offer a path to resend |
| Firebase verification links expire (~1 hour) | Old links don't work, user needs a fresh one |

---

## ✅ The Solution: "Resend Verification" Everywhere

### Step 1: Update `signInWithEmail` - DON'T Sign Out Automatically

```typescript
// lib/auth/auth-service.ts
export async function signInWithEmail(email: string, password: string) {
  try {
    const userCredential = await signInWithEmailAndPassword(auth, email, password);
    const user = userCredential.user;

    // 🛡️ Check verification status
    if (!user.emailVerified) {
      // ❌ DON'T sign out here - keep user logged in so they can resend
      // We'll handle blocking access via routing guard instead
      
      return { 
        success: false, 
        errorCode: 'EMAIL_NOT_VERIFIED',
        message: 'Please verify your email address before signing in.',
        user: user // Return user object so UI can trigger resend
      };
    }

    return { success: true, user };
  } catch (error: any) {
    return { success: false, error: handleAuthError(error) };
  }
}
```

```tsx
  }
};
```

### Step 3: Enhance `verify-email.tsx` - Add "Refresh Status" + Better UX

```tsx
// app/(auth)/verify-email.tsx - Enhanced Version
import { useState, useEffect } from 'react';
import { View, Text, StyleSheet, ActivityIndicator, Alert, Platform } from 'react-native';
import { useRouter, useLocalSearchParams } from 'expo-router';
import { 
  sendEmailVerification, 
  signOut, 
  onAuthStateChanged,
  getAuth
} from 'firebase/auth';
import { auth } from '@/lib/firebase';
import { Button } from '@/components/ui/button';
import { Ionicons } from '@expo/vector-icons';

export default function VerifyEmailScreen() {
  const router = useRouter();
  const params = useLocalSearchParams<{ email?: string; fromLogin?: string }>();
  
  const [isSending, setIsSending] = useState(false);
  const [isChecking, setIsChecking] = useState(false);
  const [userEmail, setUserEmail] = useState<string | null>(params.email || null);
  const [message, setMessage] = useState('');

  useEffect(() => {
    const unsubscribe = onAuthStateChanged(auth, (user) => {
      if (user) {
        setUserEmail(user.email);
        
        // ✅ Auto-check: If user verified email externally, redirect to home
        if (user.emailVerified) {
          setMessage('Email verified! Redirecting...');
          setTimeout(() => router.replace('/(tabs)/home'), 1500);
        }
      } else if (!params.fromLogin) {
        // Only redirect to login if they didn't come FROM login
        router.replace('/login');
      }
    });
    return () => unsubscribe();
  }, [params.fromLogin]);

  // ✅ Resend Verification Email
  const handleResendEmail = async () => {
    if (!auth.currentUser && !userEmail) {
      Alert.alert('Error', 'No user session found. Please try logging in again.');
      return;
    }

    setIsSending(true);
    setMessage('');
    
    try {
      // If we have a logged-in user, use them
      if (auth.currentUser) {
        await sendEmailVerification(auth.currentUser);
      } else {
        // Edge case: User not logged in but has email param
        // We can't send verification without auth, so guide them to login
        Alert.alert(
          'Login Required',
          'Please log in to resend the verification email.',
          [{ text: 'OK', onPress: () => router.replace('/login') }]
        );
        return;
      }
      
      setMessage('Verification email sent! Check your inbox (and spam folder).');
      showToast('Email sent', 'mail');
    } catch (error: any) {
      console.error('Resend error:', error);
      
      // Handle specific Firebase errors
      if (error.code === 'auth/too-many-requests') {
        setMessage('Too many attempts. Please wait a few minutes before trying again.');
      } else {
        setMessage('Failed to send email. Please try again.');
      }
      showToast('Failed to send', 'alert-circle');
    } finally {
      setIsSending(false);
    }
  };

  // ✅ Check Verification Status (Refresh)
  const handleCheckStatus = async () => {
    if (!auth.currentUser) return;
    
    setIsChecking(true);
    setMessage('Checking verification status...');
    
    try {
      // Force Firebase to reload user data from server
      await auth.currentUser.reload();
      
      if (auth.currentUser.emailVerified) {
        setMessage('✅ Email verified! Redirecting to home...');
        setTimeout(() => router.replace('/(tabs)/home'), 1000);
      } else {
        setMessage('⏳ Still pending. Check your inbox or click "Resend Email".');
      }
    } catch (error) {
      setMessage('Could not check status. Please try again.');
    } finally {
      setIsChecking(false);
    }
  };

  // ✅ Go to Login (with sign out if needed)
  const handleGoToSignIn = async () => {
    if (auth.currentUser) {
      await signOut(auth);
    }
    router.replace('/login');
  };

  if (!userEmail && !auth.currentUser) {
    return (
      <View style={styles.center}>
        <ActivityIndicator size="large" color="#3b82f6" />
        <Text style={styles.loadingText}>Loading...</Text>
      </View>
    );
  }

  return (
    <View style={styles.container}>
      <Ionicons name="mail-outline" size={64} color="#3b82f6" style={styles.icon} />
      
      <Text style={styles.title}>Verify Your Email</Text>
      
      <Text style={styles.subtitle}>
        We've sent a verification link to:{'\n'}
        <Text style={styles.email}>{userEmail}</Text>
      </Text>
      
      <Text style={styles.info}>
        1. Open your email inbox{'\n'}
        2. Find the email from QR Guard{'\n'}
        3. Click "Verify Email" link{'\n'}
        4. Return to this app
      </Text>

      {/* Dynamic Message Area */}
      {message ? (
        <Text style={[
          styles.message, 
          message.includes('✅') ? styles.success : 
          message.includes('⏳') ? styles.warning : styles.error
        ]}>
          {message}
        </Text>
      ) : null}

      {/* Action Buttons */}
      <View style={styles.buttonContainer}>
        {/* Primary: Resend Email */}
        <Button 
          title={isSending ? "Sending..." : "Resend Verification Email"} 
          variant="primary"
          onPress={handleResendEmail} 
          disabled={isSending || isChecking}
          loading={isSending}
          icon="mail"
        />
        
        {/* Secondary: Check Status */}
        <Button 
          title={isChecking ? "Checking..." : "Check Verification Status"} 
          variant="outline"
          onPress={handleCheckStatus} 
          disabled={isSending || isChecking}
          loading={isChecking}
          style={{ marginTop: 12 }}
          icon="refresh"
        />
        
        {/* Tertiary: Back to Login */}
        <Button 
          title="Back to Sign In" 
          variant="text"
          onPress={handleGoToSignIn} 
          style={{ marginTop: 8 }}
        />
      </Link>

      {/* Helpful Tips */}
      <View style={styles.tips}>
        <Text style={styles.tipsTitle}>💡 Tips:</Text>
        <Text style={styles.tipsText}>• Check your Spam/Junk folder</Text>
        <Text style={styles.tipsText}>• Add noreply@qrguard.in to contacts</Text>
        <Text style={styles.tipsText}>• Verification links expire in 1 hour</Text>
        <Text style={styles.tipsText}>• Click "Resend" for a fresh link</Text>
      </View>
    </View>
  );
}

const styles = StyleSheet.create({

  center: { flex: 1, justifyContent: 'center', alignItems: 'center' },
```

### Step 4: Update Auth Guard to Allow Unverified Users on Verify Screen

```typescript
// app/_layout.tsx - Updated routing logic
useEffect(() => {
  if (loading) return;

  const inAuthGroup = segments[0] === '(auth)';
  const inTabsGroup = segments[0] === '(tabs)';
  const onVerifyScreen = segments.includes('verify-email');

  if (!user) {
    if (!inAuthGroup) router.replace('/login');
  } else {
    if (!user.emailVerified && !user.isAnonymous) {
      // Unverified email user: ONLY allow access to verify-email screen
      if (!onVerifyScreen) {
        router.replace('/verify-email');
      }
    } else {
      // Verified or Anonymous: Allow tabs
      if (inAuthGroup && !onVerifyScreen && segments[1] !== 'login' && segments[1] !== 'signup') {
        router.replace('/(tabs)/home');
      }
    }
  }
}, [user, loading, segments]);
```

## 🔐 Handling the "Email Already Exists + Unverified" Panic Scenario

When a **new user** tries to sign up with an email that exists but is unverified:

```typescript
// In signUpWithEmail function - Add this check BEFORE creating user
import { fetchSignInMethodsForEmail } from 'firebase/auth';

export async function signUpWithEmail(email: string, password: string, fullName: string) {
  try {
    // 🔍 Check if email already exists
    const methods = await fetchSignInMethodsForEmail(auth, email);
    
    if (methods && methods.length > 0) {
      // Email exists! Check if it's unverified
      // We can't directly check verification status without signing in,
      // so we guide the user to login + resend flow
      return { 
        success: false, 
        errorCode: 'EMAIL_EXISTS_UNVERIFIED',
        message: 'An account with this email exists but is not verified. Please log in to resend verification.',
        suggestLogin: true
      };
    }
    
    // ... rest of signup logic
  }
}
```

## 📱 UX Flow Summary (Fixed)

```
🔹 New User Signup:
   Enter email → Create Account → Redirect to /verify-email
   → Shows "Check inbox" + "Resend Email" + "Back to Login"

🔹 Existing Unverified User Login:
   Enter credentials → "Email not verified" → Redirect to /verify-email?email=user@example.com
   → Shows "Resend Email" + "Check Status" + "Back to Login"

🔹 User Clicks Verification Link (External):
   Opens email → Clicks link → Returns to app
   → App auto-detects emailVerified=true → Redirects to /home

🔹 User Clicks "Check Status":
   Calls user.reload() → Fetches latest Firebase state
   → If verified: Redirect to home
   → If not: Show "Still pending, try Resend"

🔹 Expired Link / Deleted Email:
   User clicks "Resend Email" → Sends fresh verification link
   → New link valid for 1 hour
```

## 🛡️ Security Considerations

| Concern | Mitigation |
|---------|-----------|
| Spamming "Resend" | Firebase rate limits: ~5/min per IP, ~100/day per project. Show user-friendly error if hit. |
| Enumerating emails | Error messages are generic: "If an account exists, we sent a verification link." |
| Unauthorized resend | Only allow resend for the currently authenticated user (or after successful password login) |
| Link expiration | Clearly communicate "Links expire in 1 hour" + provide easy resend option |
