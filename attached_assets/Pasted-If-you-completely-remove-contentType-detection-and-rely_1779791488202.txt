# Recommended Architecture

For generated QRs:

```text id="8u4l9n"
templateKey
```

should be the primary source.

For external QRs:

```text id="z3h8bm"
contentType detection
```

should be the fallback.

Example:

```ts
if (qr.templateKey) {
  renderFromTemplate(qr.templateKey);
} else {
  detectFromContent(qr.content);
}
```

This gives:

```text id="mn53qr"
Generated QRs
↓
100% centralized templates

External QRs
↓
automatic detection
```


because your scanner still needs them for non-QR-Guard codes.

# What I Would Do

Create a central registry:

```ts
TEMPLATE_REGISTRY = {
  wifi,
  upi,
  vcard,
  event,
  business,
  location,
  ...
}
```

Then:

```ts
if (qr.templateKey) {
   // Generated QR
   renderTemplate(qr.templateKey);
} else {
   // External QR
   detectAndRender(qr.content);
}
```

This gives you the best of both worlds:

✅ Generated QRs always show the correct template.

✅ Verification status stays attached.

✅ My QR and QR Detail stay consistent.

✅ Scanning random QR codes from the real world still works.

For QR Guard specifically, this hybrid approach is likely the most reliable architecture because your app handles both **user-generated QRs** and **third-party scanned QRs**.
