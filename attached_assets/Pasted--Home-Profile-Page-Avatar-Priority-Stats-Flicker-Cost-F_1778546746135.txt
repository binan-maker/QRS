# 🔍 Home & Profile Page: Avatar Priority, Stats Flicker & Cost Fix

You've identified **3 critical issues** that are directly impacting UX, perceived performance, and Firebase costs:
1. 🖼️ **Google avatar overrides app-uploaded avatar**
2.  **Profile image not loading/showing**
3. 🔢 **Stats "count" or change on every navigation** (expensive re-renders)

Here’s the exact root-cause breakdown + production-ready fixes.

---

## 📉 Root Cause Analysis

| Issue | Technical Reason | Why It Happens |
|-------|------------------|----------------|
| **Google avatar wins** | UI pulls `auth.currentUser.photoURL` directly instead of checking Firestore `avatarUrl` first | Firebase Auth syncs Google photo on login, overwriting local preference |
| **Profile image not loading** | Broken URL path, missing cache-busting, or `<Image>` component not re-rendering on state update | Storage URL format mismatch, no `key` prop, or stale React state |
| **Stats count/flicker** | Client-side number animation hook + `onSnapshot` re-fires on tab focus + no `React.memo` | Every navigation triggers re-mount or listener sync → numbers re-calculate → visual "counting" |
| **High cost** | Full doc fetches, uncached avatars, real-time listeners on static data, inline formatting | 15-30 reads/mount × tab switches × no cache |

## ✅ Fix 1: Avatar Priority Chain (App > Google > Fallback)

Replace your current avatar component with this **strict priority resolver**. It ensures the app-uploaded image always wins, falls back to Google only if no app image exists, and shows a colored initial avatar as final fallback.

```tsx
// components/ui/SmartAvatar.tsx
import { Image } from 'expo-image';
import { View, Text, StyleSheet } from 'react-native';
import { useAvatarStore } from '@/lib/store/avatarStore';
import { auth } from '@/lib/firebase';
import { useMemo } from 'react';

export function SmartAvatar({ size = 40, name = '' }: { size?: number; name?: string }) {
  const { url: appAvatarUrl } = useAvatarStore();
  const googlePhotoUrl = auth.currentUser?.photoURL;

  // ✅ Strict priority: App Upload > Google Photo > Colored Initials
  const resolvedUrl = useMemo(() => {
    if (appAvatarUrl && appAvatarUrl !== 'null') return appAvatarUrl;
    if (googlePhotoUrl) return googlePhotoUrl;
    return null;
  }, [appAvatarUrl, googlePhotoUrl]);

  const initials = name ? name.charAt(0).toUpperCase() : '?';
  const radius = size / 2;

  // ✅ Generate consistent background color from name/email hash
  const bgColor = useMemo(() => {
    if (resolvedUrl) return 'transparent';
    const hash = (name || 'default').split('').reduce((a, b) => {
      a = ((a << 5) - a) + b.charCodeAt(0);
      return a & a;
    }, 0);
    const colors = ['#3b82f6', '#8b5cf6', '#ec4899', '#f59e0b', '#10b981', '#6366f1'];
    return colors[Math.abs(hash) % colors.length];
  }, [name, resolvedUrl]);

  return (
    <View style={[styles.container, { width: size, height: size, borderRadius: radius, backgroundColor: bgColor }]}>
      {resolvedUrl ? (
        <Image
          source={{ uri: resolvedUrl }}
          style={{ width: size, height: size, borderRadius: radius }}
          cachePolicy="memory-disk"
          contentFit="cover"
          transition={200}
          key={resolvedUrl} // ✅ Forces reload when URL changes
        />
      ) : (
        <Text style={[styles.initials, { fontSize: size * 0.45, color: '#ffffff' }]}>
          {initials}
        </Text>
      )}
    </View>
  );
}

const styles = StyleSheet.create({
  container: { overflow: 'hidden', justifyContent: 'center', alignItems: 'center' },
  initials: { fontWeight: '700', textTransform: 'uppercase' }
});
```

**Usage:**
```tsx
// Home & Profile headers
import { SmartAvatar } from '@/components/ui/SmartAvatar';
<SmartAvatar size={48} name={user?.displayName || user?.email} />
```

## ✅ Fix 2: Stop Stats "Counting" & Eliminate Expense

The "counting" behavior comes from **client-side animation hooks** + **real-time listener re-syncs** on every tab switch. Here’s how to lock it down:

### 1. Remove Animation/Counting Hooks
If you have something like `useAnimatedNumber()` or `useCountUp()`, **delete it**. Stats should be static, cached values.

### 2. Stabilize Stats Component
```tsx
// features/profile/components/ProfileStats.tsx
import { memo, useMemo } from 'react';
import { View, Text, StyleSheet } from 'react-native';

// ✅ Memoized wrapper prevents re-renders when parent updates
export const ProfileStats = memo(({ scans, created, followers }: { scans: number; created: number; followers: number }) => {
  // ✅ useMemo prevents re-formatting on every render
  const fmt = (n: number) => n >= 1000 ? `${(n / 1000).toFixed(1)}K` : String(n);

  return (
    <View style={styles.container}>
      <StatBox label="Scans" value={fmt(scans)} />
      <StatBox label="Created" value={fmt(created)} />
      <StatBox label="Followers" value={fmt(followers)} />
    </View>
  );
});

const StatBox = ({ label, value }: { label: string; value: string }) => (
  <View style={styles.box}>
    <Text style={styles.value}>{value}</Text>
    <Text style={styles.label}>{label}</Text>
  </View>
);

const styles = StyleSheet.create({
  container: { flexDirection: 'row', justifyContent: 'space-around', paddingVertical: 16, backgroundColor: '#f8fafc', borderRadius: 12, marginHorizontal: 16, marginTop: 12 },
  box: { alignItems: 'center' },
  value: { fontSize: 20, fontWeight: '700', color: '#1e293b' },
  label: { fontSize: 12, color: '#64748b', marginTop: 4 }
});
```

### 3. Cache Profile Data (Zero Re-fetches on Navigation)
```typescript
// lib/hooks/useProfileData.ts
import { useQuery } from '@tanstack/react-query';
import { doc, getDoc } from 'firebase/firestore';
import { db } from '@/lib/firebase';
import { mmkv } from '@/lib/storage/mmkv';

export function useProfileData(uid: string) {
  return useQuery({
    queryKey: ['profile', uid],
    queryFn: async () => {
      const snap = await getDoc(doc(db, 'users', uid));
      const d = snap.data() || {};
      
      const data = {
        displayName: d.displayName || 'User',
        email: d.email || '',
        avatarUrl: d.avatarUrl || null,
        avatarVersion: d.avatarVersion || 0,
        stats: {
          scans: d.totalScans || 0,
          created: d.generatedCount || 0,
          followers: d.followers || 0
        }
      };

      mmkv.set(`profile_${uid}`, JSON.stringify(data));
      return data;
    },
    initialData: () => {
      const raw = mmkv.getString(`profile_${uid}`);
      return raw ? JSON.parse(raw) : undefined;
    },
    staleTime: 1000 * 60 * 5,   // 5 min cache
    gcTime: 1000 * 60 * 30,     // 30 min memory
    refetchOnWindowFocus: false,
    refetchOnMount: false,      // ✅ CRITICAL: Stops re-fetch on tab switch
  });
}
```

## ✅ Fix 3: Profile Image Not Loading/Showing

This happens when:
1. Storage URL is malformed or missing `https://`
2. No `key` prop on `<Image>` → React doesn't re-render when URL changes
3. Fallback isn't handled → blank space

**Solved by:**
- Using `SmartAvatar` above (handles null/invalid URLs gracefully)
- Adding `key={resolvedUrl}` to force React re-render on update
- Using `expo-image` with `cachePolicy="memory-disk"` + error fallback
