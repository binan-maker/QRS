# THE QR GENERATOR — COMPLETE ANALYSIS

## 1. THE FLOW (How a User Creates a QR)

```
Landing Page (qr-generator/index.tsx)
    ↓
User taps "Standard QR" or "Private QR"
    ↓
Goes to /qr-standard or /qr-private
    ↓
Those screens render QrFormPage with mode="individual" or "private"
    ↓
Inside QrFormPage:
    1. TypePickerHome shows — user taps "Choose Template"
    2. QrTemplateModal OR TemplatePickerModal opens
    3. User picks a template (URL, UPI, WiFi, etc.)
    4. InputSection appears with the right input fields
    5. User types content
    6. QR previews LIVE as they type (useEffect with 350ms debounce)
    7. User taps "Generate QR Code"
    8. If logged in: QR gets a UUID, saved to Firebase, encoded as qrg:// URL
    9. QrOutputCard shows the final QR with share/download/PDF options
```

### `features/generator/hooks/useQrGenerator.ts` — THE BRAIN
This is a **734-line monster hook** that controls everything. Here's what it manages:

| State | What It Tracks |
|---|---|
| `selectedPreset` | Which of the 28 preset types is active |
| `inputValue` | Main text input |
| `extraFields` | Secondary fields (e.g., WiFi password, UPI amount) |
| `qrValue` | The actual string that gets encoded into the QR |
| `qrMode` | `individual`, `business`, or `private` |
| `customLogoUri` / `customLogoBase64` | Uploaded logo image |
| `showDefaultLogo` | Whether to show the QR Guard logo |
| `logoPosition` | `center`, `top-left`, `top-right`, etc. |
| `selectedThemeIdx` / `customFgColor` / `customBgColor` | QR colors |
| `advancedSettings` | Scan limit, expiry date, label |
| `generatedUuid` | The unique UUID assigned to saved QRs |
| `generatedAt` | Timestamp |
| `saving` / `savedToProfile` / `savedDocId` | Save status |
| `urlRiskScore` / `urlRiskReasons` | For dangerous URL warnings |

**How `qrValue` is built:**
1. As the user types, a `useEffect` with `setTimeout(350ms)` debounce builds the raw content via `buildQrContent()`
2. If mode is `business` AND user is logged in (`isBranded`), it generates a short UUID and creates a **redirect URL** like `https://qrguard.app/guard/ABCD-1234-EFGH-5678`
3. If mode is `individual` AND user is logged in, it creates `https://qrguard.app/go/ABCD-1234...`
4. If mode is `private`, the QR encodes the **raw content directly** (no redirect URL)

**The Generate Button Logic:**
```tsx
if (qrValue exists && user logged in && NOT saved yet) 
    → "Save Protected QR"
if (qrValue exists && already saved) 
    → "Protected QR Saved ✓"
if (qrValue exists && private mode) 
    → "Private QR Generated ✓"
if (no qrValue yet) 
    → "Generate QR Code"
```

## 4. WHAT'S BROKEN, CONFUSING, OR MISSING

### 🔴 CRITICAL ISSUES

**A. The `presetActive` state is required to show inputs, but it's confusing**
In `QrFormPage.tsx`, `presetActive` starts as `false`. The `InputSection` only renders when `presetActive === true`. But `presetActive` is set to `true` only when:
- User taps a template from `QrTemplateModal` (`handleSelectPreset`)
- User selects from `TemplatePickerModal` (`handleSelectFromModal`)
- The `TypePickerHome` has a "Choose Template" button that opens `QrTemplateModal`

**The problem:** If a user goes to Standard QR → types something without picking a template, nothing happens because inputs are hidden. They MUST tap "Choose Template" first. **This is not obvious.**

**B. `business.tsx` redirects to `/qr-standard`**
Business mode doesn't exist as a standalone screen. In `useQrGenerator`, business mode logic IS present (`qrMode === "business"`), but there's no way for a user to actually enter business mode from the UI anymore. The business category selector and business form components exist but aren't wired into the active flow.

**C. Two overlapping template pickers cause confusion**
You have:
1. `QrTemplateModal` — rich custom templates (UPI Payment, WiFi, etc.) with built-in forms
2. `TemplatePickerModal` — search-based category picker from `CategoryRegistryService`

Both open from the same "Choose Template" button area. `TypePickerHome` opens `QrTemplateModal` via `onOpenCustom`. But there's also `TemplatePickerModal` that was supposed to open via `onOpenTemplates`. **The `TypePickerHome` doesn't actually call `onOpenTemplates` anywhere in the current landing flow** — the `hideActions` prop hides it after selection.

**D. `PRESET_CATEGORIES` in `presets.ts` is unused in the active flow**
The categories (Basic, Contact & Messaging, Social Media, Payments, Utility, Business & Growth) are defined but not shown anywhere in the active UI. `TemplatePickerModal` does its own categorization via tags.

**E. The `CategoryRegistryService` might be empty or broken**
`TemplatePickerModal` loads categories via `CategoryRegistryService.getAll()`. If this service returns nothing or errors silently, the modal shows empty/loading.

**F. "Generate" button vs "Save" button logic is confusing**
The button label changes 4 different ways based on state. Users might not understand that:
- Tapping once generates a preview
- Tapping again (if logged in) saves it to their account
- Private QRs are never saved

**G. `buildQrContent` handles presets 0-27, but `qr-builder.ts` also has cases 28-35**
Cases 28-35 (Razorpay, Google Maps, Discord, TikTok, Snapchat, Google Pay, Linktree, MeCard) don't have matching presets in `presets.ts`. They exist in the builder but users can't select them.

### 🟡 MEDIUM ISSUES

**H. No template selection persistence**
If the user picks "UPI Payment" from `QrTemplateModal`, `presetActive` becomes true and `inputValue` is set. But `selectedPreset` in `useQrGenerator` stays at whatever it was. The `QrTemplateModal` generates content directly — it bypasses the preset system entirely. This means:
- `InputSection` won't show the right label/placeholder because `selectedPreset` is wrong
- The content type saved to Firebase might be wrong

**I. `TypePickerHome` mode cards are hidden**
Since `hideModeCards={true}` is hardcoded in `QrFormPage`, users can't switch between Standard/Private without going back to the landing page.

**J. "Choose Template" button opens `QrTemplateModal`, not the preset list**
The user expects to see the 28 presets (URL, Email, Phone, etc.), but instead sees the rich templates (UPI Payment, Contact Card, WiFi). These are different things!

**K. `handleGenerate` creates a NEW UUID every time**
Even if you regenerate the same QR, it creates a new Firebase document with a new UUID. There's no "update existing QR" logic.

**L. PDF download on Android is overly complex**
The code tries SAF (Storage Access Framework), caches directory URIs, shows alert dialogs — this is fragile and probably breaks on many Android versions.
