2. Toast / In-App Notification — 3 Different Systems, Should Be 1
The app currently has three completely separate, incompatible toast implementations:

System A — useQrGenerator toast (features/generator/hooks/useQrGenerator.ts):

State: toastMsg, toastType, toastAnim (React Native Animated.Value)
Shows/hides using Animated.sequence with 220ms in/out timing
Rendered as an Animated.View in QrFormPage.tsx
Supports "success" and "error" types
System B — qr-detail custom toast (app/qr-detail/[id].tsx):

State: toastState object with message, icon, and key
Different animation approach, different visual design
Supports Ionicons icons as part of the toast
System C — ToastAndroid.show (features/generator/hooks/useQrGenerator.ts and features/my-qr/hooks/useMyQrDetail.ts):

Only works on Android
Used for "PDF saved to Downloads ✓" messages
No visual consistency with the other two systems
What to build instead: A single useToast hook + ToastProvider at the root layout level (app/_layout.tsx). Any screen or hook calls showToast("message", "success" | "error" | "info") globally. One visual design, one animation, works everywhere. The ToastProvider component lives in components/ui/Toast.tsx.

3. The topInset Safe Area Calculation — Copied in 30+ Files
Every single screen in app/ and several components compute safe area insets themselves using the exact same logic:

const insets = useSafeAreaInsets();
const topInset = Platform.OS === "web" ? 67 : insets.top;

Files that repeat this exact calculation (30+ occurrences):

Every file in app/(tabs)/ — 6 files
Every root screen in app/ — account-management, create-group, donation, favorites, friends, how-it-works, my-qr-codes, my-qr/[id], privacy-policy, privacy-settings, profile/[username], qr-detail/[id], qr-group/[id], qr-groups, search, terms, trust-scores — 17 files
Several files in features/ — QrFormPage.tsx, CustomQrBuilderPage.tsx
What to build instead: A single useTopInset() hook in lib/utils/platform.ts (it already exists — just add this function). Every screen imports and calls const topInset = useTopInset() with one line instead of two, and the web magic number 67 lives in exactly one place.

4. Card, Divider, and Badge Styles — 156 StyleSheet Definitions, Need a Design Token System
The entire app has 156 StyleSheet.create calls and 1,064 hardcoded font family strings like "Inter_700Bold", "Inter_600SemiBold" scattered everywhere. Three specific style objects are the worst offenders:

The "Surface Card" — defined 10+ times identically:

borderRadius: 16 (or 18 or 20 — varies arbitrarily)
borderWidth: 1
padding: 16 (or 14)
backgroundColor: colors.surface
borderColor: colors.surfaceBorder
Found in: ContentCard, OwnerCard, MerchantDashboard, LoadingSkeleton, EvidenceCard, TrustScoreCard, HistoryItem, donation.tsx, qr-detail/[id].tsx, and more
The "Hairline Divider" — defined 7+ times identically:

height: 1 or StyleSheet.hairlineWidth
backgroundColor: colors.surfaceBorder
Found in: lib/styles/common.ts, features/settings/styles.ts, ProfileSettingsSection.tsx, VerificationModal.tsx, CustomQrModal.tsx, privacy-settings.tsx, features/my-qr/styles.ts
The "Modal/Section Row Header" — defined 6+ times identically:

flexDirection: "row", alignItems: "center", justifyContent: "space-between", marginBottom: 14
Found in: VerificationModal, MessagesModal, FollowersModal, MerchantDashboard, DeleteAccountModal, app/(tabs)/index.tsx
What to build instead: Expand lib/styles/common.ts (which already exists but is underused) into a true design token file with named exports like cardStyle(colors), dividerStyle(colors), rowHeaderStyle(), pillStyle(color). Every component imports these instead of rewriting them. The font names move to constants/typography.ts as constants — FONT_BOLD, FONT_MEDIUM, FONT_REGULAR, FONT_SEMIBOLD — used everywhere instead of raw strings.

5. The REPORT_TYPES Array — Defined 3 Times in the Same Feature Folder
Inside features/qr-detail/components/, three files each define their own private copy of the same report types data:

ReportGrid.tsx — defines REPORT_TYPES with keys safe, scam, fake, spam, icons, and colors (line 16)
ReportSection.tsx — defines the same REPORT_TYPES array (line 15)
TrustScoreCard.tsx — defines the same array again (line 40)
These three are already in the same folder. If the icon for "scam" ever needs to change, you have to update it in three places. The same issue applies to the color-coding logic for content types (safe → colors.primary, warning → colors.warning, danger → colors.danger) which is repeated in ContentCard.tsx, OwnerCard.tsx, and TrustScoreCard.tsx.

What to build instead: A single features/qr-detail/data/reportTypes.ts file that exports the REPORT_TYPES constant and the content-type-to-color mapping function. All three components import from there.

6. Skeleton Loading Rows — Identical Component Written Twice in the Same Folder
Inside features/settings/components/, two files define a local SkeletonListRow component that is byte-for-byte identical:

CommentsSection.tsx lines 9–20: a row with a 40×40 circle skeleton + two text line skeletons
HistorySection.tsx lines 9–20: the exact same component with the exact same name and the exact same JSX
FollowingSection.tsx also defines a SkeletonCard that is a variation of the same pattern.

What to build instead: A single features/settings/components/SkeletonListRow.tsx file exported and imported by all three sections. This is the simplest fix in the entire codebase — 10 lines moved to one file.
