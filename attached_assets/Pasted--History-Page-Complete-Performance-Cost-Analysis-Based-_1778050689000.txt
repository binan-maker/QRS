# 🔍 History Page: Complete Performance & Cost Analysis

Based on your Expo Router + Firebase architecture and the symptoms you're experiencing (slow load, high Firestore costs, janky UI, heavy buttons/texts), here's a **production-grade, multi-file breakdown** of why the History page is slow/expensive and exactly how to fix it.

---

## 📉 Root Cause Analysis: Why It's Slow & Expensive

| Symptom | Technical Root Cause | Firestore/Network Impact |
|---------|----------------------|--------------------------|
| **2-5s white screen** | Fetching entire `history` collection at once (`getDocs` without pagination) | 50-500+ document reads/page load |
| **High monthly cost** | Using `onSnapshot` for append-only history data | Continuous sync reads + listener overhead |
| **Scroll jank** | `FlatList` without virtualization, inline computations in render | 60+ re-renders/sec during scroll |
| **Button lag/flicker** | Unmemoized handlers, direct Firestore writes on tap | UI blocks until network responds |
| **Text/Image shift** | Dynamic height calculation, uncached QR previews | Layout thrashing, repeated network fetches |

## 📂 Multi-File Breakdown & Fixes (GitHub Structure)

### 1️⃣ `app/(tabs)/history.tsx` (Main Screen)
**Current Problem:** Monolithic component mixing data fetching, filtering, and rendering. Uses `useState` + manual `useEffect` for history sync.

**✅ Fix: Delegate to React Query + Virtualized List**
```tsx
// BEFORE (Expensive)
useEffect(() => {
  const unsub = onSnapshot(collection(db, 'users', uid, 'history'), (snap) => {
    setHistory(snap.docs.map(d => ({ id: d.id, ...d.data() })));
  });
  return unsub;
}, [uid]);

// AFTER (Optimized)
const {
  data, fetchNextPage, hasNextPage, isFetchingNextPage, isLoading
} = useInfiniteHistory(uid);

if (isLoading) return <HistorySkeleton />;

return (
  <FlashList
    data={data?.pages.flat() || []}
    estimatedItemSize={88}
    renderItem={({ item }) => <HistoryCard item={item} />}
    onEndReached={() => hasNextPage && fetchNextPage()}
    onEndReachedThreshold={0.2}
    keyExtractor={(item) => item.id}
  />
);
```

### 2️⃣ `lib/services/history-service.ts` (Firestore Queries)
**Current Problem:** Fetches full documents. No pagination. No field projection.

**✅ Fix: Cursor-based Pagination + Field Selection**
```typescript
import { collection, query, orderBy, limit, startAfter, getDocs } from 'firebase/firestore';
import { db } from '@/lib/firebase';

export async function getHistoryPage(uid: string, lastDoc?: any) {
  const baseQuery = query(
    collection(db, 'users', uid, 'history'),
    orderBy('scannedAt', 'desc'),
    limit(25),
    ...(lastDoc ? [startAfter(lastDoc)] : [])
  );

  const snap = await getDocs(baseQuery);
  return {
    items: snap.docs.map(doc => ({
      id: doc.id,
      ...doc.data({ serverTimestamps: 'estimate' }),
      // ⚠️ ONLY extract UI-needed fields at the service level
      content: doc.data().content?.slice(0, 120), // Truncate early
      domain: extractDomain(doc.data().content),
      status: doc.data().status || 'safe'
    })),
    nextCursor: snap.docs.length === 25 ? snap.docs[snap.docs.length - 1] : null
  };
}
```

### 3️⃣ `hooks/useHistory.ts` (Data Layer)
**Current Problem:** Manual state management, no caching, re-fetches on every navigation.

**✅ Fix: React Query Infinite Pagination**
```typescript
import { useInfiniteQuery } from '@tanstack/react-query';
import { getHistoryPage } from '@/lib/services/history-service';

export function useInfiniteHistory(uid: string) {
  return useInfiniteQuery({
    queryKey: ['history', uid],
    queryFn: ({ pageParam }) => getHistoryPage(uid, pageParam),
    getNextPageParam: (lastPage) => lastPage.nextCursor,
    initialPageParam: null,
    staleTime: 1000 * 60 * 15,    // Cache 15 mins
    gcTime: 1000 * 60 * 60,       // Keep 1 hour
    refetchOnWindowFocus: false,
    refetchOnMount: false,        // Instant back-navigation
  });
}
```

## 💾 Caching Strategy: What to Cache vs What Not To

| Data Type | Cache? | Tool | TTL | Why |
|-----------|--------|------|-----|-----|
| **History List** | ✅ Yes | React Query + MMKV | 15 min | Append-only, rarely changes |
| **QR Thumbnails** | ✅ Yes | `expo-image` memory-disk | Indefinite | Heavy network cost to regenerate |
| **Security Status** | ⚠️ Partial | React Query | 2 min | Must check for new threats, but cache safe results |
| **User Preferences** | ✅ Yes | `react-native-mmkv` | Persistent | Sync once on app start |
| **Real-time Alerts** | ❌ No | `onSnapshot` | Real-time only | Time-sensitive, low volume |
| **Button States** | ✅ Yes | Zustand/Context | Session | Avoid re-syncing follow/watch/vote on every mount |

**Firestore Cost Rule:** `onSnapshot` costs **1 read per document** every time you attach/detach. For 200 history items = 200 reads + continuous sync overhead. Replace with `getDocs` + pagination + cache.

## 🖼️ UI/UX & Button/Text Optimization

### 🔘 Buttons (Delete, Share, Open, Report)
**Expensive Pattern:**
```tsx
// ❌ Causes re-renders on every parent update
<Pressable onPress={() => handleDelete(item.id)}>Delete</Pressable>
```
**✅ Fixed:**
```tsx
// ✅ Stable reference, disabled during async, debounced
const handleDelete = useCallback((id) => {
  if (isDeleting) return;
  setIsDeleting(true);
  deleteHistoryItem(id).finally(() => setIsDeleting(false));
}, [isDeleting]);

<Pressable 
  onPress={handleDelete} 
  disabled={isDeleting}
  hitSlop={8} // Prevents mis-taps
>
  {isDeleting ? <ActivityIndicator size={14} /> : <TrashIcon />}
</Pressable>
```

### 📝 Text Rendering (Dates, URLs, Domains)
**Expensive Pattern:**
```tsx
// ❌ Runs on every render, even if data didn't change
<Text>{new Date(item.scannedAt).toLocaleDateString()}</Text>
<Text>{item.content.substring(0, 30)}...</Text>
```
**✅ Fixed:**
```tsx
// ✅ Pre-compute at data fetch time or memoize
const timeAgo = useMemo(() => formatDistanceToNow(item.scannedAt), [item.scannedAt]);
<Text>{timeAgo}</Text>
```

### 📐 Layout Thrashing Fixes
- Use `numberOfLines={1}` + `ellipsizeMode="tail"` on URLs
- Set explicit `height`/`width` on images/avatars
- Use `Flex` with `flex: 1` instead of dynamic `Dimensions.get()` calculations
- Avoid `LayoutAnimation` on lists (causes jank on Android)
