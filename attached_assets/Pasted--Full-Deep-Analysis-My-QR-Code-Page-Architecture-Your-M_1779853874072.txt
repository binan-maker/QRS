# 6. Firestore Cost Analysis

Now the important part.

---

# Current Firestore Usage

Inside `useMyQrDetail.ts`:

You currently load:

```ts
getGeneratedQrById()
getQrFollowCount()
getQrFollowersList()
```

This means:

# The page triggers MULTIPLE Firestore reads.

---

# Cost Problem #1 — Separate Reads

Currently likely flow:

```text
1 read -> QR
1 read -> follow count
N reads -> followers
```

This scales badly.

---

# Example Scale Problem

If user opens:

100 QR pages/day

and each page triggers:

* QR document read
* followers collection read
* analytics read
* comments read

You can quickly explode Firestore reads.

---

# Current Risk Level

## MEDIUM

Not catastrophic yet.

But dangerous once users scale.

---

# Biggest Firestore Cost Risk

# Followers System

This is expensive.

Because:

```ts
getQrFollowersList()
```

likely queries subcollections.

Follower systems become VERY expensive in Firestore.

Especially if:

* realtime listeners
* sorting
* pagination missing
* large arrays
* repeated openings

---

# REQUIRED IMPROVEMENT

DO NOT load followers automatically.

Only load:

```ts
followersCount
```

initially.

Then lazy-load modal followers ONLY when modal opens.

You partially already do this.

GOOD decision.

---

# But Still Improve Further

Add:

```ts
pagination
limit(20)
cursor-based loading
```

Otherwise large creators become expensive.

---

# 7. Analytics Cost Risk

You have:


# Why Analytics Become Expensive

Analytics usually generate:

* scan events
* timestamps
* locations
* devices
* referrals
* user agents
* countries
* engagement metrics

Firestore becomes VERY expensive for analytics.

---

# CRITICAL RECOMMENDATION

Do NOT store raw analytics forever in Firestore.

This is huge.

---

# Recommended Architecture

Store:

## Firestore

ONLY:

```text
aggregated metrics
```

Example:

```json
{
  "totalScans": 1522,
  "todayScans": 44,
  "countryTop": "India"
}
```

---

# Move Raw Events Elsewhere

Raw scan logs should move to:

* BigQuery
* Supabase Analytics
* ClickHouse
* ElasticSearch
* PostgreSQL
* Cloud Functions aggregation

Firestore is BAD for heavy analytics scaling.
