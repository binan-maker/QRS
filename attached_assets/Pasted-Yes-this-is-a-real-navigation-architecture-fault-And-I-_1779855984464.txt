Yes — this is a real navigation architecture fault.

And I can explain exactly WHY it happens in your app.

This is caused by:

# Navigation stack inconsistency between:

* App back button (`router.back()`)
* Android hardware back button

Your internal back button uses the router stack correctly,
but Android hardware back is interacting with the ROOT navigation stack differently.

That means your screen hierarchy is architected incorrectly.

---

# WHAT IS HAPPENING EXACTLY

Current flow:

```text id="6f6t2h"
Home
 → Settings
   → Profile Settings
```

---

# APP HEADER BACK BUTTON

When user taps your custom back icon:

```tsx id="hn87u9"
router.back()
```

This pops:

```text id="aq0k7j"
Profile Settings
→ back to Settings
```

Correct behavior.

---

# BUT DEVICE BACK BUTTON

Android hardware back button:

```text id="klmrjg"
Profile Settings
→ Home
```

This means:

# Android thinks Settings is NOT in the active stack.

That is the real issue.

---

# ROOT CAUSE

Most likely your Settings page is opened using:

```tsx id="u0lyfy"
router.replace()
```

instead of:

```tsx id="fcxhkc"
router.push()
```

OR

you are navigating across different navigation groups incorrectly.

---

# MOST LIKELY BAD FLOW

Probably something like:

```tsx id="s1epan"

```

Then:

```tsx id="2y24g3"
router.push("/profile-settings")
```

---

# WHY THIS BREAKS

`replace()` removes previous screen from stack.

So Android stack becomes:

```text id="eb12j8"
Home
→ Profile Settings
```

NOT:

```text id="9f9dfy"
Home
→ Settings
→ Profile Settings
```

---

# RESULT

Your custom header back:

```tsx id="zcod35"
router.back()
```

works because Expo Router handles local history.

BUT Android hardware back checks native navigation stack.

So it skips Settings.

---


outside the same stack group.

# WHY THIS MATTERS

Expo Router stack history depends heavily on:

* route grouping
* stack nesting
* push vs replace

Your architecture currently breaks stack continuity.

